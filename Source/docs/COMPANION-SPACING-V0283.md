# Closer companion spacing — v0.28.3

## v0.28.7: large-party lag and exhausted spacing recovery

The live report recorded eight attached companions from the user's roughly nine-member party, many 4.8–6.8 metres away. Six had exhausted all three separation attempts. Several had lost their assigned point during the twelve-second blocked-lane fallback. A paused read-only navigation probe confirmed the desired arc coordinates projected directly onto valid ground. Replaying the live reservation logic rejected four otherwise valid seats: historical goals were still reserved, and failed attempts had advanced `travelRequestAt` into the future, extending those reservations.

Only each mobile member's current assigned seat now reserves space. Native-locked participants retain their actual-space reservation. Failed projections use a separate retry deadline, and the assigned point remains available throughout a blockage. After the initial three attempts, an immobile follower can make one recovery attempt every eight seconds instead of remaining permanently stuck until the player or actor moves. Diagnostics distinguish occupied destinations from navigation failures and include path status, request time, retry time and seat index.

The previous four-paths-per-second cap also imposed a refresh delay of over two seconds for nine members. Moving parties now receive one to three path requests per 250 ms according to party size, capped at twelve per second, while stationary parties retain four per second. Individual moving requests have a 750 ms cooldown. A shared predicted origin leads travel by half the expected refresh interval, at most 0.65 seconds or 250 cm; stopping clears prediction. The standard arc radii remain about 2.47 and 4.47 metres, so this reduces trailing lag without packing collision capsules closer together. Planar distance checks avoid treating height differences as unfinished horizontal arrival.

Validation: 184 offline tests and changed Lua syntax passed. New checks cover nine-member scheduling, bounded delayed retries, the actual reservation adapter with obsolete goals and the live ground-height difference. The paused native probe and results are in `runtime/session-v0287/` and `runtime/companion-native-formation287c.txt`; these are local diagnostics, not release assets. `mod/Development/inspect_party_formation.lua` reads the active hot-reload module cache, because an external `require` from a separately loaded development script can return an older RC5 module. To run this bounded paused probe, create `runtime/formation-audit.request` and request the existing `nativeinfo / partyaudit` development action with a fresh ID. It performs no movement or AI writes. Actual following appearance and path cost still require gameplay confirmation.

## v0.28.6: preserve arc destinations and give their paths navigation control

Live v0.28.5 diagnostics showed accepted movement requests while Ocha and Vicho settled only about 26 cm apart. Code inspection found the native Follower task remained active alongside the mod's `MoveToLocation`, and destination clearance could replace an occupied arc seat with a sideways/backward offset. Correct geometry alone did not produce the requested arrangement.

The formation adapter now reserves the assigned seats of mobile companions, rather than their transient passing positions. Locked companions reserve their actual space. Strict destination selection waits for occupied seats; it no longer shifts them into lines. A navigation failure can still trigger the existing temporary narrow-terrain fallback. Shared path budgets, retry limits and player-approach hysteresis remain active.

`ai_state.lua` provides an instance-validated formation lease. It temporarily sets `bMainBehaviorSuspended`, cancels the previous task once, and gives navigation to the requested arc path. It does not disable movement physics or animation. Repeated path updates reuse the lease. Arrival within 60 cm while settled, an eight-second timeout, combat entry, conversation, native unbreakable/cinematic actions, dismissal or an update fault releases ownership. External suspension is never acquired as our own. Combat preparation releases the lease before invoking native combat APIs; conversation selection recognizes our lease and releases it before acquiring its separate conversation hold.

`runtime/companion-formation.tsv` reports cached actual coordinates, assigned coordinates, distance to the assigned seat, path ownership, pending correction and the last request outcome. Use this alongside native diagnostics to distinguish geometry, occupancy, navigation and arrival failures without adding broad object scans.

Validation: 181 offline tests passed, including formation ownership and restoration, external holds, partial acquisition failures, conversation handoff, strict occupancy and twenty mutually reserved arc seats. Lua syntax passed. These validate adapter logic; native suspension/path behavior and the visible arrangement still require gameplay confirmation.

## v0.28.5: mirror the spawn semicircle for following

The user preferred the front spawn arc to the side/rear row layout. `followOffset` now derives its seats from `summonArc`, reflecting the forward distance behind Coen while retaining the left/right spread. Spawning and following therefore share the same radii, capsule-aware spacing and expanding arc capacities. Standard-size companions occupy the first rear arc at approximately 2.47 metres; larger parties fill wider arcs, rather than rectangular rows.

The formation still follows actual travel heading and stays fixed during short approaches/camera turns. Native combat, crowding correction, path budgets and narrow-terrain fallbacks remain in place. Tight terrain may temporarily prevent the full semicircle. The shared arc radius also checks straight-line chord clearance for large outer arcs, preventing adjacent seats from becoming too close as more companions are added.

179 offline tests and Lua syntax passed, including rear placement and spawn/follow symmetry at multiple headings for forty companions. Gameplay confirmation remains with the user. Earlier sections below describe superseded layouts.

## v0.28.4: separate player distance from body spacing

Gameplay with eight companions showed that the 1.4-metre grid crowded their bodies and animations. The current layout uses a 1.9-metre minimum grid, expanding to twice the largest capsule radius plus 80 cm. The two closest side positions remain 1.5 metres from Coen (1.65-metre native stop setting); outer seats and rear rows use the wider grid. Larger bodies also increase the nearest-player clearance.

Crowding detection now uses the two capsule radii plus 60 cm, with a 170 cm minimum, so it reacts before capsules intersect. A persistent conflict waits 500 ms before requesting movement. Crowding has a separate three-attempt budget from ordinary arrival corrections; the shared four-per-second limit, per-character cooldown and no-progress backoff still apply. Conversations, combat and other locked actors keep priority. Native navigation and collisions still determine the exact paths while moving.

Spawns use front arcs of four, seven and ten seats to accommodate the wider clearance without moving the first row excessively far away: about 2.47 metres for ordinary bodies. Twenty standard-size summons fit within 6.6 metres in open-ground geometry checks. Follow layouts were checked up to forty members; the nearest positions remain close while additional companions occupy more rows.

179 offline tests and Lua syntax checks passed. Tests cover nearby player positions with wider pairwise separation, crowding before capsule contact, projected destination clearance, locked actors, and crowding corrections after ordinary retries are exhausted. Gameplay confirmation remains necessary. The following paragraphs record the superseded v0.28.3 values.

Small parties previously used a 160 cm grid, a 175 cm native stop radius for the closest slots, and a 256 cm initial summon arc. The static formation tolerated four metres of player travel before relocating. More significantly, a successful `MoveToLocation` request cleared the arrival correction immediately: native path acceptance was being treated as evidence of arrival, so a companion could remain far from its intended spot.

The shared grid is now `max(140, 2 * largest capsule radius + 30)` cm. Normal-size companions use side/rear positions 140 cm from Coen for the closest slots, with a 155 cm native stop setting. The front summon arc starts at approximately 217 cm; subsequent arcs grow to fit larger parties. Twenty standard-size summons fit inside 5.2 metres in the open-ground geometry checks. These are target positions, not guarantees on every terrain or native path.

Spawn reservations, projected travel destinations and catch-up destinations use the full grid clearance between companions. Larger capsules increase the layout automatically, including player clearance checks for projected spawn/travel positions. Existing crowd separation still gives stationary conversation/combat participants priority and moves only the yielding member. Path work remains limited to four requests per second across the whole party, with individual cooldowns and stalled-progress limits.

The settled formation begins another travel leg after three metres. Camera rotation and short approaches retain the existing formation rather than shuffling everyone. Native restart distance uses the same three-metre allowance while settled, and the existing one-metre allowance during travel. A path request uses 25 cm acceptance. Its arrival correction stays pending until measured proximity confirms arrival, or the player approaches closely enough that holding still for conversation should take priority.

Validation: 178 offline checks passed, including twenty-member spacing at several headings, nav-projection collision rejection, large capsules, clone labels, short approaches, path budgets and actual follow-adapter acceptance behavior.
