# Game update integration — v0.30.0

18 September 2026. This update installs the supplied UE4SS 1.2.1 RC6 package and Dawnwalker Mod Menu 1.0.6.2. Existing mod activation entries are preserved; replaced files have a dated backup and relative-path manifest under `backups/`. The local game identifies itself as CL-258504. Its executable size differs from the loader archive's documented reference executable; this is a tested local integration, not a claim of identical binaries.

## Native companion UI

F5 constructs an owned UMG widget tree in the game. It contains Summon, Party, Settings and Help pages, and separate Characters / Creatures & combatants lists. Game artwork and font styling are resolved through the installed menu dependency's theme module. No dependency widgets or default objects are edited, and no game UI assets are included in the release.

The native page owns a balanced input lease and releases it on close, world change or reload. Settings change immediately and save to the installed mod's `config.ini`. The external Mod Settings page describes the same keys in `mod_settings.ini`; the game adapter reads committed file changes once per second. The old desktop F5 panel releases its hotkey when `native-ui.enabled` is present. Conversation subtitles and typing remain in the existing helper.

Summons enter the existing asynchronous queue. The menu remains usable during loading and closes after the queue completes and the player stops browsing. Party status updates change captions, rather than rebuilding the entire page on every tick. The game retains its existing paused state: queued spawns wait if the native pause menu is open.

## Combat and recovery

Default settings are 250% companion damage, 100% attack frequency, matching the player's level, and returning fallen companions after eight peaceful seconds. Health bars remain hidden. `companion_damage.lua` rebases slider changes against captured per-instance values rather than multiplying previously modified values. It changes physical base damage attributes, not every spell's bespoke damage calculation.

`companion_tuning.lua` writes the owned clone's Level and AttackSpeedMultiplierAdditive through the game's attribute setter. Player level is read from the player's ability-system attributes. No global NPC level override is used. Attack frequency is the UI name for the native attack-speed adjustment; the AI still decides when attacks and special powers are appropriate. Native ability/animation behavior can constrain the practical rate.

Faction-controller relationships to the player are applied persistently in both directions, with player hostility repaired if it reappears. Existing campaign follower damage tagging remains. This improves allegiance but is not proof that every source-specific area effect respects it: Bakir's projectile/effect route can bypass ordinary faction target selection. A combat check is still needed before claiming complete area-effect protection. The implementation does not grant player invulnerability.

When a member is defeated, its travel/combat leases are released. Recovery waits until the player and every surviving party member leave combat. Any new combat resets the timer. The existing owned spawner is stopped before a replacement is queued; the same roster identity and ordering are retained, and dismissal removes recovery eligibility. A streamed-out living member continues through the existing reconnection path rather than being treated as dead.

## Additional roster

The first category keeps 15 named conversation characters. The second has 86 asset-backed boss, enemy and animal candidates, generated from the game's captured asset registry by `Build-CombatRoster.mjs`. All carry `chat=false`: direct selection, nearest fallback, group availability and Convai prewarming exclude these copies. Named bosses in the second category retain their character-specific combat setup without acquiring a chat identity.

Individual creature spawning and fighting are not all verified. Ambient animals may lack an AI board or attacks. The regular spawn validation remains active and reports unsupported definitions rather than replacing their native AI with an invented humanoid setup. Large creatures can need substantially more navigable space.

## Transcription and audio

The microphone strip now measures the transcription using its displayed font and available width, grows vertically and wraps multiple lines. The transport retains up to 1,200 characters instead of 320. The finish key stays visible above the text.

The audio path retains decoded samples and uses the same HRTF output for direct and buffered group responses. No extra codec, pitch change or low-pass filter was added. HRTF deliberately changes the spectrum between ears to convey direction, and distance reduces volume; it is not perceptually identical to centered playback. An isolated browser render confirmed left/right direction and distance behavior. A listening test with actual dialogue remains useful for subjective quality.

## Prebuilt distribution

`Build-Prebuilt.ps1 -BundleSharedKey` produces a ZIP with a compiled helper, bundled browser code, the Node runtime, selected mod code/configuration and third-party notices. Shared defaults are compiled into a helper resource; no account setup is needed in that edition. The build removes the development player's end-user ID, local browser sessions and history. Each installation creates its own conversation identity. The account's service and LTM allowances still determine availability.

UE4SS and Dawnwalker Mod Menu remain separate requirements. The release uses the same relative structure on every PC; no npm command, compiler or developer runtime path is required. Installation and customization are documented in `PREBUILT-INSTALL.md`. The archive is a preview until the new gameplay behavior has been checked.

Nexus permits functionality-dependent network tools subject to its review process; its rules do not state a blanket executable ban. Requesting review before publishing this networked package is appropriate. GitHub can host the same ZIP. No upload has been performed. [Nexus file submission rules](https://help.nexusmods.com/article/28-file-submission-guidelines).

## Validation

All 22 UE4SS exports required by the native companion bridge are present in RC6. The native reflection probe successfully reports 40-byte soft class references and a 128-byte population spawn parameter frame. The native UMG probe constructed and released every page in the running game: 22 controls on Characters, 93 on the combat roster, 5 on the empty Party page, 13 on Settings and 5 on Help. This verifies runtime construction, not every input gesture or every resolution.

Focused checks cover slider rebasing, continuous-peace recovery, per-instance level/rate tuning, catalogue integrity, chat targeting, conversation cleanup, group audio and existing movement handoffs. TypeScript, Lua parsing and the Windows helper build are checked. Long transcription and microphone/subtitle previews were rendered. The first default-dispatch inspection exposed a stopped Lua callback; the bootstrap now explicitly schedules engine work through EngineTick, and the obsolete live-upgrade migrations have been removed. Fresh-process menu probes succeeded afterward.

The focused run passed 52 tests. The packaged Node server started independently, served the browser UI, and merged a dummy bundled configuration with the 26 distributed cloud identities without making service calls. The portable Lua bootstrap passed a Windows-path check. Archive inspection found no development installation metadata, browser profile, conversation history or temporary shared-defaults file. These checks do not replace gameplay validation of spawning, recovery, native-menu interaction or area-effect friendly fire.
